# Neural Investors Lab: Modular Hybrid Quant AI Architecture

## 1. Project Overview
Neural Investors Lab is an Autonomous Multi-Agent System designed for advanced stock market analysis. 
* **Beyond Pipeline:** Instead of a simple gather-and-summarize pipeline, it employs a **Boardroom Debate Workflow**, allowing the CEO Agent to request deep-dives if Hard Data (Python) and Narrative (LLM) conflict.
* **Risk-First:** Features a dedicated Chief Risk Officer (CRO) module to enforce strict mathematical position sizing and portfolio risk management.
* **Continuous Learning:** Integrates a Backtesting engine to evaluate past AI predictions against actual forward returns.


**Key Architectural Rules:**
1. **Separation of Concerns:** Mathematical calculations MUST be done in Pure Python. LLMs MUST NOT calculate numbers.
2. **Strict Output:** The final output from the Chief Strategist must be a validated, strict JSON object.
3. **Configuration Driven:** No hardcoded secrets or model parameters. Everything must be managed via `.env` and `pydantic-settings`.
4. **No MCP Server:** The architecture is simplified. No external MCP server is required.

## 2. Tech Stack
* **Language:** Python 3.13+
* **Package Manager:** `uv` (Lightning-fast Python package installer and resolver).
* **Database (Storage):** PostgreSQL (Utilizing `JSONB` for storing Agent outputs and logs).
* **Database (Cache & Broker):** Redis (For caching API responses to prevent rate-limits).
* **AI Provider:** OpenRouter API (Using the official `openai` Python SDK).
* **Key Libraries:** `yfinance`, `pandas`, `pandas-ta`, `newspaper3k`, `pydantic`, `pydantic-settings`, `psycopg2-binary` / `SQLAlchemy`, `redis`.

## 5. Implementation Phases (Step-by-Step for AI Assistant)

### **Part 1: Foundation, Config & Database**
* **Goal:** Establish the core infrastructure and configuration management using `uv`.
* **Tasks:**
    1. Initialize or update the project using `uv` (ensure `pyproject.toml` is configured with necessary dependencies like `pydantic-settings`, `openai`, `psycopg2-binary`, etc.).
    2. Create `docker-compose.yml` for PostgreSQL and Redis.
    3. Create `.env.example` using the structure defined in Section 4.
    4. Write `src/core/config.py` using `pydantic-settings` to parse the `.env` file (ensure boolean casting for reasoning flags).
    5. Implement `src/core/db_postgres.py` and `src/core/db_redis.py`.
    6. Define strict Pydantic models in `src/models/` for data passing.

### **Part 2: The LLM Client Setup**
* **Goal:** Build a robust OpenRouter client using the official OpenAI SDK.
* **Tasks:**
    1. Implement `src/core/llm_client.py`.
    2. Configure the client with `base_url="https://openrouter.ai/api/v1"`.
    3. Create a unified method (e.g., `generate_completion`) that accepts the model name, prompt, and a `use_reasoning` boolean.
    4. Conditionally append `extra_body={"reasoning": {"enabled": True}}` ONLY if `use_reasoning` is `True`.
    5. Support passing the unmodified `reasoning_details` back into the conversation history if multi-turn dialogue is needed.

### **Part 3: The Services Layer (Deterministic Tools)**
* **Goal:** Build the Python modules that fetch and calculate data. **Rule: No AI in this layer.**
* **Tasks:**
    1. `finance_api.py`: Fetch ticker data, historical prices (including volume), income statements, and balance sheets. Implement Redis caching with appropriate TTLs.
    2. `indicator_math.py`: Implement comprehensive institutional-grade Python formulas using `pandas` and `pandas-ta`. Return strictly typed tags/summaries for the LLM:
        * **Fundamentals:** Piotroski F-Score (0-9), PEG Ratio, Altman Z-Score.
        * **Trend & Momentum:** MA50/100/200 alignment, RSI, MACD & Histogram (Must include algorithmic detection of Bullish/Bearish Divergence).
        * **Volume & Order Flow:** MFI (Money Flow Index), VWAP (Volume Weighted Average Price), and Volume Profile approximations (e.g., finding the Point of Control / POC).
        * **Volatility & Risk Management:** ATR (Average True Range) for calculating dynamic Stop-Loss distances, Bollinger Bands (for squeeze/breakout detection), and Historical Volatility (HV).
    3. `deep_research.py`: Implement full-text article extraction using `newspaper3k` to feed clean text to the Researcher Agent.

### **Part 4: The Agents (Deterministic & AI)**
* **Goal:** Create the workflows.
* **Tasks:**
    1. `auditor.py` & `chartist.py`: Pure Python. Fetch data via Services and output strict Pydantic models (No LLMs).
    2. `researcher.py`: Uses NEWS_ANALYST_MODEL to extract sentiment. Must include an investigate_conflict(query) method for Round 2 debates.
    3. `chief_strategist.py`: Uses CEO_MODEL
      - Step 1: Ingest Auditor, Chartist, and initial Researcher data.
      - Step 2: Identify contradictions. If any, trigger the Researcher for a deep-dive.
      - Step 3: Draft the initial trading strategy (Entry, Take Profit, Stop Loss, and conviction narrative).
    4. `risk_manager.py`: (The CRO Hybrid Agent).
      - Math Step (Python): Takes the CEO's draft and applies strict Python risk formulas (e.g., Kelly Criterion, ATR-based volatility sizing, VaR).
      - Agent Step (LLM): Uses CRO_MODEL to review the CEO's narrative against the mathematical risk limits. It hnews Veto Power to overwrite the CEO's position sizing if it violates risk threshnews.
      - Output: Returns the absolute final, strictly validated JSON object based on `synthesis_schema.py`.

### **Part 5: Orchestration, Debate Loop & Telegram UI**
* **Goal:** Tie all agents together into a "Boardroom" workflow with strict risk oversight and real-time monitoring.
* **Tasks:**
    1. **Centralized Logging:** Implement standard Python `logging` across all modules. Ensure the console outputs clear, timestamped logs for: 
       - Incoming Ticker requests.
       - Progress of each Agent (Auditor, Chartist, Researcher).
       - CEO decision logic and any "Debate" triggers.
       - Final Risk Manager approval/veto.
    2. **`main_orchestrator.py` (The Boardroom):**
       - Use `asyncio` to run `Auditor`, `Chartist`, and `Researcher` (Round 1) in parallel for maximum speed.
       - **Logic (The Debate):** Implement a check where the `Chief Strategist` identifies contradictions. If a conflict is found, trigger the `Researcher` for a targeted "Deep-Dive" (Round 2) before finalizing the draft.
       - Pass the CEO's draft to `Risk Manager` for mathematical position sizing.
       - Save the FINAL output (JSONB) to PostgreSQL for future backtesting.
    3. **`formatter.py`:** Create a robust utility to parse the CEO/Risk Manager JSON into clean, readable HTML/Markdown for Telegram, utilizing Emojis for status and clear sections for S/R levels and Entry/Exit plans.
    4. **`telegram_bot.py`:** Use `python-telegram-bot` (or similar) to handle user commands. Integrate with the Orchestrator and ensure all secrets are pulled from `src/core/config.py` (via `.env`).

### **Part 6: Evaluation & Backtesting Framework**
* **Goal:** Create a feedback loop where the AI learns from its past performance and proves its edge.
* **Tasks:**
    1. **`evaluation/backtest_engine.py`:**
       - Develop a standalone script that queries the PostgreSQL database for historical "Buy/Accumulate" recommendations.
       - For each recommendation, fetch the actual price data from `yfinance` for `T+7` (7 days later) and `T+30` (30 days later).
       - Calculate the accuracy: Did it hit the `take_profit`? Did it trigger the `stop_loss`? What was the max drawdown?
    2. **Performance Analytics:**
       - Generate a periodic report (Markdown or JSON) summarizing:
         - **Win Rate:** Percentage of successful trades.
         - **Profit/Loss:** Average return per recommendation.
         - **Pattern Analysis:** Identify if the AI is failing on specific sectors or market conditions (e.g., "High failure rate on Small-cap stocks").
    3. **Automated Cron/Task:** (Optional) Setup a task to run this backtest weekly and output a summary directly to the Telegram admin console.

## OpenAI SDK Code example from OpenRouter
```text
from openai import OpenAI

client = OpenAI(
  base_url="https://openrouter.ai/api/v1",
  api_key="<OPENROUTER_API_KEY>",
)

# First API call with reasoning
response = client.chat.completions.create(
  model="google/gemini-3.1-flash-lite",
  messages=[
          {
            "role": "user",
            "content": "How many r's are in the word 'strawberry'?"
          }
        ],
  extra_body={"reasoning": {"enabled": True}}
)

# Extract the assistant message with reasoning_details
response = response.choices[0].message

# Preserve the assistant message with reasoning_details
messages = [
  {"role": "user", "content": "How many r's are in the word 'strawberry'?"},
  {
    "role": "assistant",
    "content": response.content,
    "reasoning_details": response.reasoning_details  # Pass back unmodified
  },
  {"role": "user", "content": "Are you sure? Think carefully."}
]

# Second API call - model continues reasoning from where it left off
response2 = client.chat.completions.create(
  model="google/gemini-3.1-flash-lite",
  messages=messages,
  extra_body={"reasoning": {"enabled": True}}
)
```
